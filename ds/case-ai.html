A design system AI agents can read

I built a pipeline of seven Claude Code skills. It takes a component from a brief to a documented Figma master, with metadata and Markdown docs that an agent can read.

Situation

Components were made for people, not agents

A component in Figma had a name and a look. An AI agent could not tell when to use it, or when not to. Building one by hand also took days.

Task

Build it, then make it ready for AI

Each component needed a build in Figma, a usage doc in Markdown, metadata on the master and a doc page. The docs go into the repo, so agents read the same source as people.

Action

Seven skills, a gate after each one

Each skill does one step and reads what the step before it wrote. Nothing moves on until a designer approves it.

  1. BriefThe need, every state and property, and product research.The designer ticks or strikes each state, then approves.
  2. Build in FigmaThe component set, through the Figma CLI. Library parts, variables and text styles only.The designer reviews the set and prunes it.
  3. Usage docA Markdown file in the repo: when to use it, and when not to.The designer reads the "when" sentence and the "when not" list.
  4. MetadataCategory, usage, "not for" and tags on the Figma master.An explicit yes after the diff. It writes to the live library.
  5. Doc pageOverview, anatomy, variants, states, content, accessibility, related.The designer reviews the page.
  6. Routing checkA fresh agent picks components for real needs and for near misses.Any need that routes to two components gets fixed.
  7. Eval (optional)A prompt-only build against the pipeline build.The designer picks A or B blind, before the numbers.

Publishing the library stays manual. No skill publishes it.

Action

Four rules that keep it honest

The brief is the answer key

The build, the doc and the eval all read the approved brief. A line struck in the brief is not built and not documented.

One source for usage text

The Markdown doc generates the Figma description and the index. We change the doc and run again. Nobody edits the output.

Builds never copy earlier builds

A build that opens an earlier attempt carries its mistakes forward, and the eval means nothing.

Cost: every run starts clean, so it takes longer.

Check the file before every write

The Figma CLI can run in a different file from the one in front. The pipeline checks the file key before it writes.

Result

Nine components in two and a half days

Nobody had logged hours for the old way, so I estimated them from ticket dates and team update posts.

Limits I put on the claim

  • Different scopeThe old way includes exploring options and choosing a direction. The pipeline run may not.
  • Never measuredInferred from dates while tasks overlapped. Real hands-on time is probably lower.
  • One run, by meNine components say little about review rounds, harder ones or other designers.
